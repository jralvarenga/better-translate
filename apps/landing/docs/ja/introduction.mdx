# Better Translate とは？

多くの翻訳設定はシンプルに始まりますが、徐々に型の安全性を失っていきます。部品をつなぎ合わせ、後から追加の宣言や手動の型付け、フレームワーク固有の修正で型安全性を取り戻そうとします。動作はしますが、決して完全に信頼できるものには感じられません。

Better Translate はそのアプローチを覆します。型安全性は最初から組み込まれており、後付けではありません。翻訳を一度定義すれば、どこでも確信を持って使えます。

## なぜ存在するのか

翻訳ツールは多くの場合、次のような問題を抱えています。

- スタック間で一貫性がない
- 緩い型付け（または型付けなし）
- フロントエンドとバックエンド間での共有が難しい

新しいプロジェクトを始めるたびに、別の翻訳ツールを学び直すことになります。Better Translate はそのサイクルを止めるためにあります。

- キーが間違っていれば、入力中に気づけるべきです
- メッセージにパラメータが必要なら、それが強制されるべきです
- 翻訳が共有されるなら、ひとつのシステムとして振る舞うべきです

推測は不要です。静かな失敗もありません。「何か見落としていないか？」という不安もありません。

## 背後にある考え方

目標はシンプルです：**ひとつの翻訳のやり方。どこでも。完全に型付けされて。**

新しいプロジェクトを始め、スタックを切り替え、Web・バックエンド・モバイルを構築しても、学び直す必要はありません。Better Translate はあらゆる TypeScript プロジェクトで動作します。例外はありません。

フレームワークごとのツールやパターンの寄せ集めではなく、スタック全体に付いてくる、単一で一貫したモデルです。

## それが意味すること

Better Translate は、次のようなチーム向けに設計されています。

- 完全に型付けされた翻訳キー
- 強制されるメッセージパラメータ
- アプリ横断で統一された翻訳システム
- 最小限のセットアップで最大のコントロール
- あらゆる環境で予測可能な動作

より多くのツールを足すことではなく、不確実性を取り除くことが目的です。
