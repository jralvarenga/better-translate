# MD & MDX

ドキュメント、ブログ、コンテンツページがローカライズされた `.md` や `.mdx` にあるときは `@better-translate/md` を使います。

このパッケージはコアトランスレーターを置き換えません。すでに作ったトランスレーターのロケールルールを読み込みます。

## 1. パッケージをインストールする

```sh
npm install @better-translate/core @better-translate/md
```

## 2. トランスレーターを作る

`src/i18n.ts` を作成します：

```ts
import { configureTranslations } from "@better-translate/core";

const en = {
  docs: {
    title: "Docs",
  },
} as const;

const es = {
  docs: {
    title: "Documentacion",
  },
} as const;

export const translator = await configureTranslations({
  availableLocales: ["en", "es"] as const,
  defaultLocale: "en",
  fallbackLocale: "en",
  messages: { en, es },
});
```

## 3. コンテンツフォルダを作る

同じルートの下にロケールごとのフォルダを置きます：

```txt
content/docs/
  en/
    getting-started.mdx
  es/
    getting-started.mdx
```

## 4. Markdown ヘルパーを作る

`src/docs.ts` を作成します：

```ts
import { createMarkdownHelpers } from "@better-translate/md";

import { translator } from "./i18n";

export const docs = createMarkdownHelpers(translator, {
  rootDir: "./content/docs",
});
```

## 5. 1つのドキュメントを読む

```ts
import { docs } from "./docs";

const englishDoc = await docs.getDocument("getting-started", {
  locale: "en",
});

const spanishDoc = await docs.getDocument("getting-started", {
  locale: "es",
});
```

## 6. 出力が必要ならコンパイルする

```ts
const compiled = await docs.compileDocument("getting-started", {
  locale: "en",
});

compiled.kind; // "md" or "mdx"
compiled.path;
compiled.usedFallback;
```

## サーバーヘルパーを使うタイミング

アプリがすでにサーバーでリクエストロケールを解決している場合は、`@better-translate/md/server` を使うと Markdown の読み込みが同じリクエストロケールに自動で従います。

## ローカライズ Markdown を自動生成する

CLI の `markdown.rootDir` オプションで Markdown ファイルの翻訳を生成できます：[CLI ガイド](/docs/cli)
