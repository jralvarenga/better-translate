# ¿Qué es Better Translate?

La mayoría de las configuraciones de traducción empiezan siendo simples y luego pierden seguridad poco a poco: conectas piezas entre sí y más tarde intentas recuperar la seguridad de tipos con declaraciones extra, tipado manual o parches específicos del framework. Funciona, pero nunca se siente del todo fiable.

Better Translate invierte ese enfoque: la seguridad de tipos está integrada desde el principio, no se añade después. Defines tus traducciones una vez y las usas en todas partes con total confianza.

## Por qué existe

Las herramientas de traducción suelen ser:

- inconsistentes entre stacks
- débilmente tipadas (o sin tipos)
- difíciles de compartir entre frontend y backend

Y cada vez que empiezas un proyecto nuevo acabas aprendiendo otra herramienta de traducción. Better Translate existe para romper ese ciclo.

- Si una clave está mal, deberías saberlo mientras escribes
- Si un mensaje requiere parámetros, deberían exigirse en tipos
- Si las traducciones se comparten, deberían comportarse como un solo sistema

Sin conjeturas. Sin fallos silenciosos. Sin «¿me dejé algo?».

## La idea detrás

El objetivo es simple: **una sola forma de traducir. En todas partes. Con tipos completos.**

Empiezas un proyecto nuevo, cambias de stack, construyes web, backend o móvil: no tienes que reaprender nada. Better Translate funciona en cualquier proyecto TypeScript. Sin excepciones.

No es una colección de herramientas ni patrones por framework, sino un único modelo coherente que te acompaña en todo el stack.

## Qué implica

Better Translate está pensado para equipos que quieren:

- claves de traducción totalmente tipadas
- parámetros de mensaje obligatorios
- un sistema de traducción unificado entre apps
- configuración mínima con control máximo
- comportamiento predecible en cada entorno

No va de añadir más herramientas, sino de quitar incertidumbre.
